# v1.2.0 — Campaign Blueprint

v1.2.0 seals the arbitrary custom-start workflow with one declarative campaign blueprint.

## Added

- `sao.aincrad.campaign-blueprint.v1`;
- `validate_campaign_blueprint` for full semantic validation on a cloned authoritative runtime;
- `preview_campaign_blueprint` for a non-mutating resulting-state preview;
- `apply_campaign_blueprint` for one-shot setup application after complete off-state validation;
- one blueprint can declare campaign-local Skills, Sword Skills, weapons, armor/shields, consumables, ordinary items, characters, proficiencies, equipment, inventory, progression rules and declarative custom mechanics;
- preview IDs are intentionally provisional/omitted, while apply returns the committed actor and item state;
- blueprint apply never finalizes setup automatically; `finalize_campaign_setup` remains an explicit authority boundary.

## Transaction semantics

Validation and preview clone the complete persisted runtime and execute the same blueprint implementation used by apply. Apply first completes the blueprint against that cloned state; only a fully successful result is committed back to the authoritative runtime. A failure in a later Sword Skill, item grant, character rule or mechanic therefore does not leave the live setup half-applied.

The persistence schema remains `sao.aincrad.save.v4` because blueprints only compose state types already persisted by v1.1. The blueprint format has its own versioned schema.
